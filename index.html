ESM + Import Maps

Two independent micro-frontends sharing one store. No bundler. No plugin. Just the browser.

Both panels show the same store uid — proof they received the same module instance, not a copy.

How it works

01

Modules are native

Since 2017, every major browser understands import and export. Add type="module" to a script tag and you are in the module system — no transpiler, no bundler, nothing to install. 

<!-- index.html — runs exactly like this in the browser -->
<script type="module">
  import { greet } from './greet.js';
  greet('world');
</script>

<!-- greet.js -->
export const greet = (name) => console.log(`hello, ${name}`);

Each file is its own scope. Nothing leaks to window. Imports are resolved relative to the file making them.

02

Bare specifiers & the import map

import '@clover/store' uses a bare specifier — not a relative path, not a URL. Without an import map the browser rejects it. The import map is a single JSON block in <head> that tells the browser how to resolve them. 

<script type="importmap">
  {
    "imports": {
      "@clover/store": "./clover/store.js"
    }
  }
</script>

That is the entire shared-dependency configuration. One JSON object, no build step required. In production you would generate this JSON from a version manifest at deploy time — but the browser mechanism is exactly the same.

03

Same URL = same instance

The browser caches every module by URL after the first fetch. When mfe-counter.js and mfe-logger.js both write import '@clover/store', the import map resolves both to ./clover/store.js. The cache sees the same URL and returns the same object — no second fetch, no copy. 

// mfe-counter.js
import { store } from '@clover/store';  // → ./clover/store.js  (fetched)

// mfe-logger.js  (completely separate file, loaded separately)
import { store } from '@clover/store';  // → ./clover/store.js  (cached ✓)

That is why both panels above show the same store uid. The uid is generated once when store.js first executes. Both MFEs received the same reference — not a copy. No webpack shared scope. No __webpack_require__. The browser module cache is the singleton mechanism.

04

Dynamic import loads MFEs lazily

Static import runs at parse time. Dynamic import() is async — it returns a Promise and lets you decide when to load a module. This is how a host shell loads micro-frontends on demand. 

// host bootstrap — the entire loading sequence
const { mount: mountCounter } = await import('/mfe-counter.js');
const { mount: mountLogger  } = await import('/mfe-logger.js');

mountCounter({ element: document.getElementById('mfeCounterRoot') });
mountLogger ({ element: document.getElementById('mfeLoggerRoot') });

Calling import() with the same URL a second time is free — the cached module is returned immediately with no network request and no re-execution of module-level code.

05

The MFE contract is just a function

Each MFE exports one thing: a mount function. It receives a DOM element, renders into it, subscribes to shared state, and returns an unmount cleanup. No framework adapter. No registration call. No shared scope init. 

// mfe-counter.js
import { store } from '@clover/store';

export const mount = ({ element }) => {
  element.innerHTML = `<button id="dec">−</button>
    <span id="val">${store.getCount()}</span>
    <button id="inc">+</button>`;

  const unsub = store.subscribe((n) => {
    element.querySelector('#val').textContent = n;
  });
  element.querySelector('#inc').addEventListener('click', store.increment);
  element.querySelector('#dec').addEventListener('click', store.decrement);

  return () => { unsub(); element.innerHTML = ''; }; // unmount
};

06

No build tool — open the file, it runs

Every file in this demo is plain JavaScript. There is no package.json, no node_modules, no config file. Serve the directory over HTTP and open index.html. 

# any static file server works
npx serve .

Import maps are supported in Chrome 89+, Firefox 108+, Safari 16.4+, and Edge 89+. For older browsers, a small polyfill (es-module-shims) drops in as a single script tag with no changes to your modules. 

<!-- polyfill for older browsers, if needed -->
<script async src="https://ga.jspm.io/npm:es-module-shims@1.10.0/dist/es-module-shims.js"></script>

<!-- import map and modules stay exactly the same -->
<script type="importmap"> ... </script>
